# Generation: data the operation map could keep

## Reaching for

I want the map to make a useful assertion at each crossing among mathematics, code and language, and to preserve enough structure for an atlas to transport that assertion honestly. A data kind earns its cost when a named consumer can use a receipted row. Breadth comes first here. Every candidate is generation, including proposed consumer changes, costs and falsification criteria. No row is a truth claim or an assertion of novelty against the literature.

## Seeds

The pinned readings in 01-reading.md; the operator's six axes; D6-086 as a transform whose useful derivative rule lives outside its entry; D9-X28 and X29 as contracts with code bindings kept by their consumer; D2-118 and D2-117 as a composition where contraction needs a condition; and the atlas paper's compatible views over shared library objects. These are seeds, not evidence for any generated design. Applying inverse (C15) to a lossy representation preserves only the recoverable equivalence class; asking for identity beyond that breaks. Applying composition (C22) to survey records preserves declared dependencies but cannot create a missing proof.

M = mathematics, C = code including formal proof artifacts, L = language. A proposed reader below requires the named adapter/change; no candidate is claimed to be consumed unchanged by existing production code. Quantities in costs are planning ranges, not measured timings.
