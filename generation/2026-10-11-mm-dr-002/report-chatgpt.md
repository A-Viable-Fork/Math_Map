# MM-DR-002 — Android bindings and the limits of boundary enforcement

**Research date:** 2026-10-11 UTC. **Platform source pin:** `android-16.0.0_r4` (Android 16 QPR2, build `BP4A.251205.006`). **Overall verdict:** **DEAD** for unrestricted, origin-sensitive enforcement by observing Android boundaries alone; **MARGINAL** for a precisely bounded set of access-controlled effects.

## 1. Executive Summary

**RESULT / THEOREM — DEAD as broadly claimed.** Android 16 QPR2 has substantial access mediation, but a checked API call does not establish complete data provenance, historical compartment origin, or noninterference. Binder authenticates the immediate caller; permission checks authorize resource access; SELinux and UID network rules constrain principals and objects. These mechanisms do not collectively authenticate every dependency of the bytes later emitted by an app. A boundary-only Regulator cannot recover origins erased by in-process copying or mixing, and published sensor and shared-resource channels demonstrate why resource access checks are weaker than information-flow confinement. The earliest fatal step is Q5 step 1 **when “every effect” includes every information/authority influence**; under the narrower meaning “explicit supported OS resource access,” step 1 is only MARGINAL, and exact ancestry attribution fails at step 3. A defensible system must restrict its effect universe, mediate explicit transfers through trusted brokers, conservatively propagate origins, and mark excluded/unverified channels **unenforced**. AppFunctions provides a dispatch/declaration surface, not an effect-conformance verifier.

**RESULT.** The same operation has different effects under different parameters. An implicit broadcast resolves receivers at runtime [S-bcast](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r4/services/core/java/com/android/server/am/BroadcastController.java), [S-bskip](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r4/services/core/java/com/android/server/am/BroadcastSkipPolicy.java); a direct socket has an actual network endpoint [S-syscalls](https://android.googlesource.com/platform/bionic/+/refs/tags/android-16.0.0_r4/libc/SYSCALLS.TXT), [S-bpf](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/tags/android-16.0.0_r4/service/src/com/android/server/BpfNetMaps.java). An in-device destination can preserve the *placement of that particular new copy* without proving E9-LOCAL for every other copy. Passing a writable fd delegates authority that survives later removal of the URI grant used to obtain it [S-pfd](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r4/core/java/android/os/ParcelFileDescriptor.java), [S-uri](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r4/services/core/java/com/android/server/uri/UriGrantsManagerService.java). Android's shared-memory protection reduction applies to future mappings, not existing mappings [S-shared](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r4/core/java/android/os/SharedMemory.java). These are reasons to bind endpoint/resource/version/recipient state, not assign invariant status to an API name alone.

**RESULT.** Kotlin calls to Java framework APIs use the same checks. Kotlin function types, suspension and coroutine scheduling do not add compulsory Android information-flow tracking. The pure-evaluation and lexical-handler rows therefore remain unverified contracts, rather than being mapped to a similarly named scheduler API.

### Boundary-observation impossibility argument

**THEOREM — relative to the stated observation model.** Assume the monitor sees boundary transaction identities and payloads, configured grants, syscall targets and timing, but not protected in-process data/PC dependencies. An app legitimately reads both a W-origin value and a public value with identical byte string `b`, then emits `b` through an allowed endpoint. Consider two executions with identical ingress and egress calls: one chooses the W value, the other the public value, using an unobserved local selection. Choose the selection implementation so its exposed boundary trace is identical. The observation is the same while the dependency root of the emitted value differs. Any monitor whose decision depends only on that observation makes the same decision in both executions. It therefore cannot simultaneously allow the genuinely public output and deny the W-derived output according to **exact** E9-ORIG-sensitive policy. This proves an information deficit for that monitor, not an impossibility of stronger runtime instrumentation.

The proof concerns dependency provenance, not guessing from byte content. It permits a sound conservative decision: treat every future output from that process as potentially W-derived once W enters it. That decision sacrifices precision and requires ingress/alias lifecycle control. Merely “one compartment per process” is insufficient if that process imports data from other compartments without propagating their origins. Tracking addresses or matching byte strings alone does not capture branch/PC influence.

**THEOREM / GENERATED example — not a newly alleged Android CVE.** A guest app supplies text to a permitted intermediary; the intermediary converts it to a new string, stores it, then returns it through an AppFunction or provider. Android can record the guest at the first transfer and the intermediary at the last, but no compulsory certificate connects the returned string to the original text or to the branch decisions it influenced. An agent can therefore receive guest-derived text **without the final platform boundary recording its transitive guest origin**, even though earlier calls recorded immediate callers. Claiming that Android never records any source would overstate this finding. A signed envelope helps only if the entire adapter/runtime preserves and correctly derives labels; self-asserted metadata is not evidence of guest absence.

**RESULT.** An explicit display/audio output may have a checked service call; light, sound and their later physical observations are not thereby subject to a digital-origin policy. The four hyperproperties require the declared observer to specify these observations. Sensor/timing examples are fatal to unrestricted influence confinement, but do not automatically falsify a deliberately narrower explicit digital-transfer theorem. The distinction must remain visible to `compose`, rather than treating excluded effects as preserved.

**Verdict: MARGINAL as a metadata/declaration surface; DEAD as a stock behavioral conformance guarantee.** This section separates the pinned implementation from evolving online docs. The presence of `restrictCallersWithExecuteAppFunctions` metadata alone must not be advertised as proof that this execution path uses it for an effect policy.

**GENERATED.** An E9 effect profile could live in an application schema or a protected companion registry keyed by package signer, package/version digest, user, function ID and handler configuration. At r4, the platform has no verified checker comparing that profile with every actual behavior of the app. Arbitrary custom XML tags are not automatically indexed policy fields. Static certification, a trusted restricted interpreter, or fail-closed mediation of all admitted effect interfaces is required before such a declaration can establish E9-EBND. Checking only observed calls can detect some deviations; it does not prove no hidden/side-channel effects occurred.

## 7. Q5 — Feasibility of a Magisk-delivered Regulator

**Verdict: DEAD for the five-step universal claim.** Magisk module packaging and root authority are deployment mechanisms, not a proof of universal hooks or complete information-flow attribution. Its documented policy overlays/scripts [D13] can change the environment; that fact does not provide a supported all-effects interception API. “Without modifying the platform” must distinguish **no ROM rebuild** from **no runtime/framework/policy change**. Hooks and policy patches may avoid rebuilding a ROM while still changing its trusted enforcement behavior.

### Fatal versus locally repairable gaps

| Failure mode | Consequence for the claimed system | Local or structural? |
|---|---|---|
| Zero-permission motion/magnetic sensor channels | Fatal to unlimited influence confinement; not proof that SensorService is absent. A system can exclude/deny these ingresses. | Sensor admission policy is a **local** enforcement point; identifying the true physical origin from its samples is **structural** for boundary-only observation. |
| Shared storage/CPU/cache/scheduling timing | Ordinary per-object access checks can all succeed while information is inferred. Profiles do not establish E9-TNI. | **Structural** shared-resource observation; architecture, resource partitioning or observation/scheduler model changes are required for a proof. |
| Two origins in one process | Exact root classification after ordinary copying/PC influence is unavailable. Killing/clearing the process later does not repair history. | **Structural** relative to the boundary-only monitor; trusted taint/IFC runtime or conservative contamination changes the observation model. |
| Revocation after exporting raw authority | Future operations may use already acquired handles or independent grants. | **Local** if capability stays behind a trusted revocable proxy whose every commit checks generation; copied data and historical effects remain irrevocable. |
| Preflight policy check versus later effect commit | Policy/owner/version/nonce can change between check and use. | **Local** for a backend that checks and consumes at one linearization point; not solved by another unrelated permission check. |
| External send plus local authenticated log | A crash/interleaving can leave an effect without the required atomic record. | **Structural to the chosen commit protocol**; a local outbox atomically logs an intent, not the remote recipient's effect. A cooperative transaction protocol or weaker semantics must be explicit. |

### Strongest defensible reformulation

**GENERATED — MARGINAL until implemented and checked:** “The Regulator enforces a declared set of **explicit digital transfers** between named UID/user compartments and named brokers on a pinned device configuration. All admitted transfers use trusted adapters that preserve authenticated ingress labels or conservatively mark unknown/contaminated ancestry; every origin-sensitive sink checks current policy against the actual bound destination and operands. Untrusted apps cannot bypass those sinks or use unaccounted raw handles. Noncooperating brokers are treated conservatively or denied. Physical and shared-resource timing observations are expressly excluded and reported unenforced; no E9-CNI/E9-TNI/E9-PNI theorem is inferred from the access controls.”

For the example “W-derived data never leaves the device,” a useful coarse variant is to forbid network and other outward transfers from every W-contaminated principal **and** forbid W from giving bytes/capabilities to any less-restricted intermediary, unless a trusted broker propagates the contamination. UID packet blocking alone is insufficient: an unrestricted recipient can send on W's behalf. A single-compartment process rule helps memory partitioning only when cross-compartment ingresses and reused/shared process state are included in that rule. Root, the Regulator, trusted brokers, key services and relevant kernel/HALs must be inside the declared trusted computing base; an adversary controlling them invalidates the guarantee.

**GENERATED — proposed composition treatment, not a landed patch.** For missing labels/gates, `compose` should return **unenforced** with the source/parameter reason. Keep “unobservable,” “unknown,” “policy denied,” “not modeled” and “verified preserved” distinct. A digital egress trace violation remains violated after delete, revocation, encryption or reclassification. Sampling a nonce must not discharge E9-FRESH; verify-signature must not discharge E9-OWNER; AppFunction metadata must not discharge E9-EBND. Incomplete operands must not match a joint-input contract.

## 8. Bottom-Line Assessment

**DEAD:** the proposed universal boundary-observation mechanism does not establish the supplied complete-origin and all-influence guarantees. **MARGINAL:** closed, enumerated, fail-closed access/transfer policies with trusted adapters and conservative origin propagation are defensible. The report supplies binding leads and source receipts, not an implemented or experimentally validated reference monitor. Attack fix status, OEM behavior and universal Magisk observability remain explicitly unverified where evidence is missing.
