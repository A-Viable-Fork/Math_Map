# MM-DR-004 — Desktop bindings and vocabulary measurement

**Pinned assessment date:** 2026-10-11. **Overall verdict: DEAD for the universal desktop claim; MARGINAL for a restricted, explicitly modeled compartment.**

## Executive summary

[RESULT] [GENERATED] NixOS at nixpkgs `7c8764b7c7b09b34f632464276218ef9090eaa11` supplies enforceable access, namespace, syscall, device and selected broker controls, but neither universal per-effect causal attribution nor complete byte/PC provenance: admitted shared mappings, passed descriptors and relaying services separate the resource gate from the actual data source. The exact dynamic W contamination rule cannot be compiled to stock options alone; the included module conservatively confines every W-capable worker as W from launch. **Q4’s necessary change is one refinement of the existing compartment-context label to protected process-incarnation, inheritance and reset semantics, with explicit subject/reset/boundary parameters; no new invariant, carrier or context-label name is forced by this policy.** This semantic gap also exists in the supplied Android export. A shared interactive desktop and other booted OSes exceed the conditional confinement claim. Timing/physical channels are excluded, never preserved.

## Q4 — Main result: vocabulary and W policy

**Verdict: NEEDS REFINEMENT for vocabulary; DEAD for exact dynamic options-only realization; MARGINAL for the conservative sketch.**

[GENERATED] Fix B to the digital resources on this machine **during the configured boot**, including local W files, mappings, devices, logs and broker effects; root/human policy administration, kernel/PID 1 and the selected storage hardware are trusted. `e9-local(W,B)` concerns present copies; `e9-noegress(W,B)` forbids historical modeled explicit exports. Ciphertext retains W origins. These are distinct; deleting a copy later never repairs historical no-egress. The observer excludes timing/resource/occurrence inference and physical channels, and cannot thereby claim `e9-cni`, `e9-tni` or `e9-pni` for a general program.

[GENERATED] The contamination clause is: for each stable process incarnation p, a successful modeled W-origin read monotonically joins W into protected `compartment-context(p)` before any concurrent effect can commit. Until authorized reset, every emitted payload/action is conservatively treated as W, including outputs that may in fact be constant. This is a **policy emission context**, not a fabricated assertion that each constant has a genuine W dependency: exact historical `Origins(v)` and provenance witnesses remain separate and are never rewritten by overtainting. Child execution and delegated work must preserve the relevant context, and all modeled reads include mappings, decrypt, task joins and IPC results. This can be stated using existing system-state/trace carriers and needs no newly invented provenance invariant.

[RESULT] Weir (Nadkarni, Andow, Enck, Jha; USENIX Security 2016, B1) is prior art for system-wide DIFC and process-context handling on Android. Its lazy polyinstantiation addresses problems with naïvely floating contexts; it is not evidence that stock Linux options implement an atomic floating label or all-channel noninterference. The attached Android table does not provide that runtime either. [S145](source-index.md) [S144](source-index.md)

### What options can implement

[GENERATED] [HEURISTIC] `q4-w-policy.nix` chooses a conservative subset: any worker permitted to read W is **W from launch**, isolated as account `agent-w`, with `agent-public` separate. It uses a restricted root, read-only secret-free store, W input bind and private local W state; isolated network/IPC/tmp and private `/dev/shm`; no devices/GPU, capabilities or new namespaces; denied privileged/mount/debug/io_uring APIs; null output/error/input; no host `/run` bus/display/PipeWire/Nix socket. The executable is an inert sleep placeholder to be replaced by audited local worker code; it is not a deployed agent. All directive/module paths are in option-catalog.json. ### What needs runtime

[GENERATED] The exact **initially public process reads W, then all later outputs are W until reset** transition needs an IFC runtime/interpreter or broker that owns all modeled input/egress. It must atomically serialize read/latch with effect commit across threads, inherited fds/maps, fork/exec and delegated services, preserve protected origin/context metadata and refuse stale tickets. A read audit followed by a cgroup/firewall update races with concurrent sends; a filesystem read filter cannot label later arbitrary RAM transformations. Kernel hooks or an eBPF LSM/proxy are heavier alternatives only for the channels they actually cover; no such full implementation was verified here. NixOS can configure/start this runtime, but generating a systemd unit does not implement it.

[GENERATED] Reset is a trusted operation with a clean-state argument: destroy the contaminated process/thread/shared-memory domain and relevant descendants, drop retained authority, then create a fresh incarnation with only certified clean inputs. `exec`, clearing a Boolean, closing a subset of fds or a reused UID/PID is not automatically reset. Persistent W state is still W and contaminates its next reader. A label-aware broker that later returns W data also recontaminates the process. The conservative sketch simply never returns its W worker to a public context.

[GENERATED] Initial whole-boundary locality and the preexisting no-egress trace prefix are premises. Applying a new module neither inventories unknown historical W copies nor repairs a prior export. The sketch constrains future operations of the launch domain, conditional on those initial premises and the declared TCB.

## Final assessment

**Verdict: DEAD for the unqualified conjunction of universal per-effect attribution, options-only dynamic IFC and whole shared/dual-boot desktop confinement.**

[HEURISTIC] [GENERATED] The strongest defensible reformulation is: **during a defined NixOS boot, under an honest enumerated TCB and an explicit digital-channel model, launch W-capable agents in always-W accounts/services with no external network, shared writable memory/files, host GUI/audio/device/IPC/daemon authority, and only local W storage; enforce the resource boundary with existing kernel/systemd/NixOS controls. For mixed public/W execution and scoped release/reset, configure a separately audited runtime that preserves protected process contexts and exact commit/replay/owner rules across every permitted broker.** The module is a reviewable sketch of the first part; the dynamic runtime, target hardware, live deployment and multi-boot closure remain unverified. This does not preserve excluded timing/physical channels or claim complete D9 provenance from Nix's configuration graph.
